# 02. 비용 설계 — 3개 안의 비교

아키텍처 선택은 기술 취향이 아니라 **서비스 단계에 맞는 비용 결정**이라고 봤습니다.
세 가지 구성을 서울 리전(`ap-northeast-2`) 온디맨드 요금 기준으로 산정해 비교했습니다.

> 산정 시점의 공개 요금 기준이며, 실제 청구액은 트래픽과 사용 패턴에 따라 달라집니다.

---

## 플랜 A — 완전관리형 (ECS Fargate)

| 서비스 | 스펙 | 단가 | 월 비용 |
|---|---|---|---|
| ECS Fargate (API) | 0.5 vCPU / 1GB, 상시 1 task | vCPU $0.05106/h · Mem $0.00561/h | $28 |
| ECS Fargate (Worker) | 0.5 vCPU / 1GB, 상시 1 task | 동일 | $28 |
| RDS PostgreSQL | db.t3.micro, 20GB gp3 | $0.034/h + 스토리지 | $28 |
| ElastiCache Redis | cache.t3.micro | $0.025/h | $18 |
| ALB | 기본 요금 + LCU | $0.025/h + $0.008/LCU | $20 |
| S3 | 50GB + 요청 | $0.025/GB | $5 |
| ECR | 이미지 2GB | $0.10/GB | $1 |
| CloudWatch | 로그 5GB/월 | $0.76/GB | $4 |
| **NAT Gateway** | 데이터 처리 | $0.059/h + $0.059/GB | **$45** |
| 데이터 전송 | 아웃바운드 10GB | $0.126/GB | $2 |
| | | **합계** | **≈ $179 / 월** |

### 산정하고 나서야 보인 것

**NAT Gateway가 전체의 25%였습니다.** 프라이빗 서브넷의 태스크가 ECR에서 이미지를
받고 S3에 파일을 올리는 트래픽이 전부 NAT를 지나기 때문입니다. 그런데 이 두 목적지는
**AWS 내부**입니다. S3와 ECR에 VPC Endpoint를 붙이면 해당 트래픽이 NAT를 우회하고,
애플리케이션 코드는 한 줄도 바뀌지 않습니다.

아키텍처 다이어그램만 그렸을 때는 NAT Gateway가 구석의 작은 상자였습니다. 항목별로
숫자를 적고 나서야 그것이 두 번째로 비싼 항목이라는 게 드러났습니다. **비용 산정은
설계가 끝난 뒤의 서류 작업이 아니라 설계의 일부**라는 걸 여기서 배웠습니다.

## 플랜 B — 절감형 (EC2 + 관리형 데이터 계층)

| 서비스 | 스펙 | 단가 | 월 비용 |
|---|---|---|---|
| EC2 t3.medium | 2 vCPU / 4GB (API + Worker 공용) | $0.0456/h | $33 |
| RDS PostgreSQL | db.t3.micro, 20GB | $0.034/h | $28 |
| ElastiCache Redis | cache.t3.micro | $0.025/h | $18 |
| ALB | 기본 | — | $20 |
| S3 | 50GB | — | $5 |
| CloudWatch | 로그 5GB | — | $4 |
| Elastic IP | 1개 | $0.005/h (미연결 시) | $1 |
| | | **합계** | **≈ $109 / 월** |

플랜 A 대비 **39% 절감**. 대신 API와 Worker가 같은 인스턴스를 공유하므로, 인식 작업이
CPU를 점유하면 API 응답이 함께 느려집니다. 확장도 인스턴스 타입을 키우는 수직 확장뿐입니다.

데이터 계층을 관리형으로 남겨둔 것은 의도적입니다. 여기서 더 줄이려면 PostgreSQL과
Redis를 EC2에 직접 올려야 하는데, 그러면 백업·시점 복구·장애 조치를 전부 직접 책임져야
합니다. 아낄 수 있는 금액이 월 $46이고 잃는 것이 데이터 안전성이라면 남는 거래가 아닙니다.

|---|---|---|---|
| EC2 t3.small | 2 vCPU / 2GB | $0.0228/h | $17 |
| RDS PostgreSQL | db.t3.micro | $0.034/h | $28 |
| ElastiCache Redis | cache.t3.micro | $0.025/h | $18 |
| S3 | 20GB | — | $2 |
| Elastic IP | 1개 | — | $1 |
| | | **합계** | **≈ $66 / 월** |

ALB를 빼고 인스턴스의 nginx가 TLS를 종단합니다. Let's Encrypt 인증서를 쓰면 ACM +
ALB 조합($20/월)을 통째로 아낄 수 있습니다. 대신 인증서 갱신을 직접 운영해야 합니다
([03. TLS와 CI/CD](03-tls-cicd.md)).

## 약정 할인

트래픽이 안정된 뒤에 적용할 수 있는 절감입니다.

| 서비스 | 온디맨드 | 1년 예약 | 절감률 |
|---|---|---|---|
| EC2 t3.medium | $33/월 | $21/월 | 36% |
| RDS db.t3.micro | $28/월 | $18/월 | 36% |
| ElastiCache t3.micro | $18/월 | $12/월 | 33% |

플랜 B에 약정을 적용하면 월 $109 → $81입니다. 다만 1년을 묶는 결정이므로, 인스턴스
타입이 확정되기 전에는 적용하지 않는 편이 낫습니다.

## AI API 외부 비용

인프라와 별개로 청구되며, 트래픽에 정비례해 늘어나는 유일한 항목이라 따로 관리했습니다.

| 항목 | 과금 방식 | 예상 (100건/일) |
|---|---|---|
| LLM (경량 모델) | Input $0.80/M · Output $4/M tokens | $5~15 |
| 이미지 인식 API | $1.50 / 1,000건 | $5 |
| 임베딩 | $0.025/M tokens | 문서 적재 시 일회성 |

토큰 사용량과 추정 비용을 호출 단위로 기록하도록 만들었습니다. 모델을 교체할 때 단가
테이블에 행을 추가하지 않으면 **비용이 조용히 0으로 적히기 때문에**, 등록되지 않은 모델은
알 수 있게 해두는 것이 중요했습니다. 측정되지 않는 비용은 관리할 수 없습니다.

| 수평 확장 | ○ | △ | ✕ |
| 무중단 배포 | ○ | △ | ✕ |
| 단일 장애점 | 없음 | 인스턴스 | 인스턴스 |
| 운영 부담 | 낮음 | 중간 | 높음 |

검증 단계에서는 플랜 C에 가까운 구성으로 시작했습니다. 사용자가 아직 없는 서비스에
월 $179의 가용성을 지불하는 것은 문제를 잘못 고른 것이라고 판단했습니다.

동시에 **옮겨갈 경로를 막지 않는 것**을 조건으로 걸었습니다. 파일 저장을 추상화해 S3로
바꿔 끼울 수 있게 하고, 설정을 환경변수로 분리하고, 같은 컨테이너 이미지가 ECS에서도
동작하도록 만들어 두었습니다. 싸게 시작하는 것과 싸게 갇히는 것은 다릅니다.
